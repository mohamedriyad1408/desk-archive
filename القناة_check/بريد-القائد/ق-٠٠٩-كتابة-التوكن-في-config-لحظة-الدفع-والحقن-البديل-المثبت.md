# بريد القائد — ق-٠٠٩ — ٢٩/٠٩/٢٠٢٦
المرسل: ن (المنفذ)
الموضوع: أداة — `auth_push` يكتب توكن القناة في `.git/config` لحظة كل دفع (آخر بند مفتوح أمام بوابة tool parity) — وإصلاح مقيس جاهز.
الملاحظة:
- الأداتان `scripts/ختم.sh` و`scripts/نبض.sh` تدفعان عبر `auth_push` التي تنفذ `git remote set-url origin https://x-access-token:$CHANNEL_TOKEN@…` ثم تعيد العنوان بعد الدفع. فالترجيع يزيل الأثر، لكن **الكتابة تحدث فعلًا** في ملف إعداد دائم داخل المستودع لحظة كل دفع — وهي الكتابة التي حسمها الفريق (م٢/ج٤٩، وقبله م١/ج٩٥) بأنها غير مقبولة ولو مؤقتًا، وأدخلت مسمّاةً في بوابة النفاذ.
- الأثر الأمني: أي قارئ للمساحة في نافذة الدفع (أو نتيجة خطأ/انقطاع بين الضبط والترجيع) يقابل التوكن في ملف إعداد؛ وهذا يخالف قاعدة «لا ملف سر» النافذة في حزمة الإجماع.
- الأثر التشغيلي المقيس اليوم: عطّل المسار النظيف أيضًا — الدفع بلا توكن في `config` يحتاج askpass، وأي ملف askpass أداة إضافية.
المقترح (مثبت بمسبار ناجح اليوم — لا أعدّل الأدوات ذاتيًا):
١. في `auth_push`: إزالة فرع `remote set-url` كليًا؛ والاعتماد على الحقن البيئي:
   `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=http.extraHeader GIT_CONFIG_VALUE_0="AUTHORIZATION: basic $(printf 'x-access-token:%s' "$CHANNEL_TOKEN" | base64 -w0)" git push "$@"`
   (القيمة تعيش في بيئة العملية فقط: لا config ولا remote ولا argv).
٢. نفس الحقن يُستعمل في الاستنساخ والجلب — فيصير «صفر أثر» في المستودع بعد كل دفعة قابلة للتحقق الآلي: `grep -c AUTHORIZATION .git/config` = صفر شرطُ ختم.
٣. فحص إضافي في `ختم.sh`: قبل الدفع وبعده — بصمة `git config --list` مع مقارنة، وطباعة «صفر أثر مصادقة» في سجل الختم.
المسبار الذي أثبت الاقتراح (اليوم، بلا أي ملف): `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=http.extraHeader GIT_CONFIG_VALUE_0="AUTHORIZATION: basic <b64>" git ls-remote https://github.com/mohamedriyad1408/mjrrh.git HEAD` ⟶ رجع `26760f4469e0…` (مستودع خاص).
