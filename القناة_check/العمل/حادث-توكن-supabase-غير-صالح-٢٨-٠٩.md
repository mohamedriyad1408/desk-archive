# حادث اعتماد: توكن Supabase غير صالح — ٢٨/٠٩/٢٠٢٦

- **النوع:** فشل اعتماد (credential غير صالح) — **ليس** اختراقًا ولا تسريبًا ولا تخلّيًا بمعنى بروتوكول-الحوادث-بأمر-المالك؛ فلا احتواء من النوع (أ) ولا مسار (ب). لا مورد خارجي مُسّ ولا بيانات تعرضت.
- **الواقعة:** ضمن دفعة أسرار المالك الأربعة (٢٨/٠٩)، فُحص SUPABASE_ACCESS_TOKEN فور الاستلام قبل أي استخدام: `GET https://api.supabase.com/v1/projects` ⇒ **HTTP 401 Unauthorized**؛ أُعيد على `/v1/organizations` ⇒ **401**. الصيغة والطول سليمان (sbp_‎…‎، ٤٤ حرفًا، بلا فراغات). الحكم: **التوكن غير صالح / منتهٍ / غير مُنشأ في الحساب الصحيح**.
- **الأثر الصفري المثبت:** لم يُستخدم التوكن في أي نداء كاتب، ولم يُبنَ عليه أي عمل — الفحص سبق الاستخدام (fail-fast). التوكن الباطل محجوز في البيئة فقط، بلا أي تسرب لملف.
- **الاحتواء المكافئ (قرار م١):** البوابات الخمس المرتبطة بتوكن Supabase **تبقى مغلقة رسميًا حتى ورود توكن صالح يجتاز الفحص نفسه**:
  ١. تفعيل مش٥ الحي · ٢. تزويد أول عميل تجريبي في مش٦ · ٣. قياس بوابات postgres الـ٣٩ وسياسات RLS (فجوة الأمن القائمة في التقييم) · ٤. الهوية الحية · ٥. مش١٠.
- **ما لا يتأثر:** بطاقة ن-067 (مش١ — GitHub فقط) تجري؛ ومش٢–مش٤ قبل أول محطة Supabase أصلًا.
- **الطلب المرتد للمالك:** توكن Supabase صالح (Personal Access Token من لوحة الحساب) — **بند واحد فقط يحجب الآن**.
- **الحالة:** ~~مفتوح~~ **مُقفل ٢٨/٠٩** — وصل التوكن البديل واجتاز الفحص نفسه (HTTP 200 على `/v1/projects` و`/v1/organizations`). الوقائع في `سجل-أسرار-البيئة.md`، والإقفال منقوش في الحالة (ج٦٨). **الدرس المثبت:** فحص fail-fast قبل أي استخدام منع البناء على اعتماد مكسور — كلفة الحادث صفر بناء ضائع.
