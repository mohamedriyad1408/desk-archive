# الخطة التنفيذية الأولى — **خطة التأسيس** (٢٨/٠٩/٢٠٢٦)
**المؤلِّف:** م١ (نية وأمر المهمة) · **المرحلة:** أول خطة تنفيذية بعد اكتمال البحث والتقاطع والتقييم — **تُعرض للإجماع الثلاثي شرط البناء (بند المالك ٨):** توقيع ن قابلية ← توقيع م٢ معايير ← توقيع م١ أمر. **لا بناء قبل اكتمال التوقيعات الثلاثة.**

## ٠) نطاق الخطة وحدُّها
- **النطاق:** **مرحلة التأسيس** لمنصة **MJRRH** فقط — من مستودع بناء جديد من الصفر إلى جاهزية البنية والعقود والحراس التي يُبنى عليها أي نواة/رحلة لاحقة. **لا تتضمن** بناء أي نواة نشاط أو رحلة عميل أو واجهة منتج أو محتوى قطاعي — تلك خطط لاحقة تقف على هذا الأساس.
- **الحدّ مطابقًا لنية المالك:** بناء من الصفر على مكدسه (GitHub · Supabase · Vercel) مع **استيراد المحرك بأبواب ق١٥** (بند ٥)، والعزل قاعدة-لكل-عميل، وكل قرارات البطاقات السبع (د٧).
- **السندات (`source_ref` لكل بند):** `واردة-المالك-٢٧-٠٩-تفويض-البحث-والبناء.md` · `المنهج-المركّب-لعمل-الخطة-٢٧-٠٩.md` · `تقاطع-البحث-٢٧-٠٩-النتيجة-المعتمدة.md` (نسخة ٢ موقَّعة ثلاثيًا: v-415/v-419/v-422) · `بروتوكول-منع-الشرود-والحراس-الصادقة-٢٧-٠٩.md` (نسخة ٢) · `بحث-م٢-مبادئ-المعمارية-والهندسة-والأمن-٢٧-٠٩.md` (أ١–أ١٢ · ق١–ق١٨) · `تقييم-الوضع-القائم-٢٧-٠٩-نسخة٢.md` (§١–§٨ — مادة قياس مثبتة v-430) · `بحث-ن-جرد-المستودعات-وما-يُستورد-٢٧-٠٩.md` · `هيكل-الخطة-التنفيذية-الأولى-٢٨-٠٩-مسودة-م١.md`.

## ٣) الترتيب الطوبولوجي الملزم (ق١٧) — لا توازٍَ في البناء
`مش١ ← مش٢ ← مش٣ ← مش٤ ← مش٥ ← مش٦ ← مش٧ ← مش٨ ← مش٩ ← مش١٠`
كل مهمة تمنع التالية بدءًا قبل إقفالها بنقش وختم ودليل مكتمل العقد. **سقف الخطر الأعلى:** مش٦ (مفاتيح) ومش٨ (مسؤولية أمنية) — وبكليهما لا نشر حيّ قبل بوابة التوكن.

## ٥) بوابتا التوكن المدمجتان — وتُطلبان دفعة واحدة عند أول محطتها
- **توكن Supabase** قبل: تطبيق مش٥ الحيّ · تزويد أول عميل تجريبي في مش٦ · قياس بوابات postgres الـ٣٩ وسياسات RLS الـ١٢ (فجوة التقييم) · مش١٠ (أرقام الحساب الحية).
- **توكن Vercel** قبل أول نشر: تفعيل خدمة جسر وواجهة على الإنترنت والدرب الخلفي للمهام >٦٠ ثانية Pro.
- **حزمته الإدارية تُقدَّم مع الطلب** (لا متفرقة): حذف المستودع الفارغ `MJRH-INDUSTRIAL-REVOLUTION-` · أرشفة `MJRH` القديم · الملف المصري (صورة الجريدة/رأي مخول) · ميزانية اعتماد: **$10/شهر/عميل على Supabase Pro** + Vercel Pro — ولا نشر قبل علمه بالمبلغ الأول وتوقيعه.

## ٦) أحكام الشرود والحراس أثناء التنفيذ
بروتوكول الشرود نسخة ٢ جزء ملزم: تعريف الشرود بفنونه الأربعة · الحكم من خمس خطوات (وقف ← عزل ← دليل ← rollback إن كان آمنًا وإلا compensation ← إعادة التأليف بجولتين ثم درس) · عقد الحارس الاثني عشر قبل أي «أخضر» · قاعدة التسمية المعتمدة · **flaky/skip/tool-error = لا أخضر** · توزيع النفي بحسب الخطر · سلسلة التوريد «المختبَر هو المنشور». والقرار المكتوب وحده الموجود — وأي تحويل عن هذه الخطة = شرود بمعناه المقيس.

## ٧) سجل الحراس المبدئي الموروث لسجل المستودع الجديد (بقواعد التسمية)
| الحارس | الصيغة المعتمدة |
|---|---|
| WORM الأحداث والدفتر | صادق **بمقام معلن كامل** (٤/٤ عمليات × طفرة وسلوك مباشر) |
| فريدية التكافؤ/التسلسل | صادق بـclaim مضيّق: **القيم غير NULL** المحكومة بنص المخطط (`''` قيمة عادية تُقبل مرة ويُرفض تكرارها) |
| توازن القيد المزدوج | صادق **عند مسار الختم فقط** + عيب INSERT المباشر معلن بقائمة الدين |
| بوابة الغلاف | صادق بمقام صغير معلن |
| CHECK اختلاف الحسابين | صادق بمقام معلن (طفرة ⇒ ٣١٧ فشلًا + سلوك مباشر + اختبار نصي) |
| حدود السيادة | يمرّ **بشاهدين سالبين** (get_event · get_events_for_aggregate)، **والصدق العام غير محسوم** — مشروع ترقية بشروط م٢ الخمسة بخطة لاحقة |
| سلسلة التجزئة | تقتل ٤/٤ طفرات مسماة — **والصدق العام غير محسوم** — مشروع oracle مستقل + طفرات الحذف/الإدراج/الترتيب/إعادة التشغيل بخطة لاحقة |
| بوابات postgres (٣٩) وسياسات RLS (١٢) | **غير مقيسة** — حتى توكن Supabase |

## ٨) التوقيع الثلاثي (ق١٨ — ترتيبه ثابت ولا بناء قبل اكتماله)
- ⬜ **ن — قابلية التنفيذ:** الخطوات قابلة بالترتيب · نتائجها المتوقعة صادقة بمقدماتها · لا اعتماد خفي · حدود التوقف والرجوع صادقة. (بطاقة ن-065)
- ⬜ **م٢ — معايير القبول:** الوفاء بق١–ق١٨ كما وضعت §٤ · الأدلة سالبة وموجبة كافية · الحراس بعقودها · بلا معيار جديد بعد الرؤية إلا حدًا أمنيًا أعلى معلنًا. (بطاقة م٢-067)
- ⬜ **م١ — الأمر النهائي:** المهام داخل نية المالك وتفويضه · لا تعارض مع مقفل · يُكتب بعد التوقيعين السابقين كتابةً. (يوثَّق في القناة بنقش استئذان الأمر)
