## أولًا — ما دعمتُه بالقياس

### ١٫١ القاعدة (§١) — **تبنّي طلب توسّعي صحيح الصياغة**
**«برهان الجدوى في خدش لا يُدفع»** كما صاغها م١ **أدقّ مما طلبتُ**: فقد أضافت «**ويُدفع مرة
واحدة عبر بوابة المهمة كاملة**» — وهذا **يمنع تراكم الخدوش**. **أُدعمها حرفًا.**

### ١٫٢ قرار «لا كيان قسم في النواة» (§٢٫١) — **مُدعَّم ببرهاني**
قياسي في المخرج (٢) أثبت أن `execute_transaction` قبلت `aggregate_type="purchase_order"`
**بلا أي تعديل في `engine.py`**. **فالقسم = عائلة عقود + توجيه + شاشات مولّدة** — **مُدعَّم.**

### ١٫٣ الترتيب «أ» (§٣) — **أُدعمه وأُشدّده برقم**
م١ يبدأ بالمشتريات لأنها «الوحيدة ذات البرهان الجاهز». **وقياسي يجعل هذا رقمًا لا رأيًا:**
```
عقد محوّل جديد            = 13 سطرًا + 3 اختبارات + فكّ قفل عدد بموضعين   (مخرج ٢ — مُنفَّذ)
بوابة أنواع العقد         = 10 أسطر · صفر كسر                            (مخرج ٦ — مُنفَّذ)
فحص رابط العقد بالمحوّل   = 41 + 45 سطرًا · 5 اختبارات                   (مخرج ٦ — مُنفَّذ)
عقدة عقد (بيانات)         = ~1290 حرفًا ⇒ ~14.6 بند شاشة
شجرة قسم (بيانات)         = ~7740 حرفًا ⇒ ~350 بند شاشة
```
**فـ«أرخص فتحة» = المشتريات برقم: عقد واحد (13 سطرًا) + إعادة استخدام محوّلين قائمين
(`inventory_transformer` · `invoice_transformer`) — مُثبت أنه يجري بلا كسر وبلا حالة ثالثة.**

## ثانيًا — **البند أ-٣ مُنفَّذ: بوابات postgres على خادم حقيقي — 23 نجحت**

**هذا ما طلبته المسودة حرفًا** («تشغيل `code/postgres` (١٢٤٠ سطرًا) على قاعدة حقيقية — أوامر
التشغيل + النتائج مختومة في القناة قبل أول مستأجر»). **فنفّذتُه:**

### ٢٫١ الأوامر (للتوثيق في القناة)
```bash
sudo apt-get install -y --no-install-recommends postgresql postgresql-client   # PostgreSQL 17.10
sudo -u postgres /usr/lib/postgresql/17/bin/initdb -D /tmp/pgdata -U postgres --auth=trust
sudo -u postgres /usr/lib/postgresql/17/bin/pg_ctl -D /tmp/pgdata \
     -o "-k /tmp/pgrun -p 5433 -c listen_addresses=127.0.0.1" -l /tmp/pg.log start
pip install "psycopg[binary]"                                    # v3.3.5 (لا psycopg2 — conftest يستورد psycopg)
psql -c "CREATE ROLE m0_owner LOGIN PASSWORD 'm0_owner_ci_pwd' BYPASSRLS"
psql -c "CREATE ROLE m0_app   LOGIN PASSWORD 'm0_app_ci_pwd'   NOBYPASSRLS"
psql -c "CREATE DATABASE m0gates OWNER m0_owner ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0"
PGHOST=127.0.0.1 PGPORT=5433 PGDATABASE=m0gates python3 -m pytest code/postgres -q
```

### ٢٫٢ النتيجة
```
23 passed in 0.32s
```
**والبوابات التسع كلها:** توازن القيد (١) · الذرّية (٢) · التكافؤ (٣) · التتبع (٤) · تعدد
المجالات (٥) · **الحدود السيادية RLS (٦)** · تعارض الحسم بلا اتصال (٧) · الإلحاقية (extra) ·
**شجرة العقود في postgres (m1)**. **والمخطط ٥ جداول: `events · ledger_entries · aggregates ·
contract_nodes · security_audit_logs`.**

### ٢٫٣ **كشف تشغيلي حاسم (لم يكن في المسودة) — يُضاف بوابةً**
عند إنشاء القاعدة بترميز `initdb` الافتراضي (`SQL_ASCII` مع locale ‏C) **فشلت البوابات كلها**:
```
UnicodeEncodeError: 'ascii' codec can't encode character '\u2014' in position 96
   psycopg/_queries.py:167
23 errors
```
**وبإنشائها `ENCODING 'UTF8' … TEMPLATE template0` ⇒ 23 passed.**

**⇒ الاعتراض/الإضافة:** **بوابة أ-٣ يجب أن تنصّ على «قاعدة UTF8 من `template0`» صراحةً.**
**فأي نشر يُهيّئ القاعدة بترميز غير UTF8 يسقط عند أول نص عربي** — والنظام كله عربي (أسماء
الحسابات · الأوصاف · عقود الأقسام). **وهذا عطل نشر لا عطل اختبار، ولن يظهر في CI إلا على
خادم حقيقي — وهو بالضبط سبب وجود البند أ-٣.**

**وفخّ ثانٍ مُقيس:** الاختبارات تستورد **`psycopg` (v3) لا `psycopg2`** — **وتثبيت `psycopg2`
وحده لا يكفي** (وقِستُه: `ModuleNotFoundError: No module named 'psycopg'`).

## ثالثًا — اعتراض هندسي واحد (§٤ المرحلة ب)

**نصّ المسودة:** «**بوابة كل قسم تُقاس قبل الشروع فيه** (على نهج العقد التاسع: خدش مقيس لا يُدفع)».

**الاعتراض:** **هذا يترك `GATED_MODULES` بلا اتساع** — والعيب البنيوي القائم أن الطبقات
(`contracts` · `questions` · `gsi` · `dependency` · `governance`) **خارج `GATED_MODULES`**، فتُختبر
بpytest مستقل بينما الحزمة unittest. **فقياس بوابة كل قسم في خدش ثم حذف الخدش يعني أن البوابة
لا تبقى حارسة بعد الدمج.**

**المقترح المقيس:** **أن تُدفع بوابات الأقسام كاختبارات في `code/tests/` مع كل قسم** (لا أن
تبقى في الخدش)، **وأن يدخل `code/contracts` و`code/questions` في `GATED_MODULES` عند أول قسم**
— **فالبوابة التي لا تُدفع ليست بوابة بل لقطة** (١٠٫٢).

**وكلفته مقيسة:** بوابة أنواع العقد 10 أسطر + فحص الرابط 41+45 — **وهي قابلة للدفع كاختبارات
دائمة بلا كسر** (قِستُ: `372 OK · CI PASS · SEED 15` بعد إضافتها في الخدش).

## رابعًا — **زاويتى للعتبة (§٥): كلفة التشغيل مقيسة لا مقدَّرة**

**م١ يقول:** الكلفة الهامشية دالة في **حجم الأحداث** لا عدد الشاشات/الأقسام. **أُدعمه — وأُعطيه
أرقامه من قياس فعلي على الخادم:**

| القياس (على postgres حقيقي) | القيمة |
|---|---|
| متوسط صف `events` | **806 بايت** (أقصى 1952) |
| متوسط صف `ledger_entries` | **123 بايت** |
| نسبة القيود إلى الأحداث | **26/24 ≈ 1.08** |
| متوسط صف `contract_nodes` | **1797 بايت** (يُدفع مرة لكل عقدة، لا لكل حدث) |
| أكبر `payload` | 1740 بايت |

**⇒ الكلفة التراكمية لكل مستأجر (مشتقة من القياس):**

| حجم الأحداث شهريًا | التخزين التراكمي/شهر |
|---|---|
| 1٬000 | **~0.9 م.بايت** |
| 10٬000 | **~9.0 م.بايت** |
| 100٬000 | **~89.6 م.بايت** |
| 1٬000٬000 | **~895.7 م.بايت** |

**الاستنتاج الهندسي (زاويتى):**
١. **التخزين ليس عنق الزجاجة** — فمليون حدث شهريًا ≈ 0.9 ج.بايت/شهر. **عنق الزجاجة هو حساب
القرّاء (الحمض · الاختناقات) فوق المجرى**، وهو **لم يُبنَ بعد** (في صندوق «مفقود» لدى م١) —
**فلا يُقدَّر رقم العتبة قبل قياس كلفة القرّاء.**
٢. **`contract_nodes` (1797 بايت) يُدفع مرة لكل عقدة لا لكل حدث** ⇒ **وهذا يثبت قياسًا أن
إضافة قسم لا ترفع الكلفة الهامشية** — **فكلام م١ مُدعَّم بالقياس لا بالاستنتاج.**
٣. **اقتراحي للحدّ الفاصل:** أن **يُؤجَّل رقم العتبة إلى ما بعد قياس كلفة القرّاء** (المرحلة ج)،
**وأن يُعتمد الآن المبدأ وحده** (حد الفئة = حجم الأحداث شهريًا) — **فوضع رقم قبل قياس القرّاء
يكون تخمينًا، والتخمين ممنوع (١٠٫٢).**
