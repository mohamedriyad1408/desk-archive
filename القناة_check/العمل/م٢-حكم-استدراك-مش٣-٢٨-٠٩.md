# ١) ب٣ — deny-by-default ومصفوفة الكائن/الوظيفة والحد الأدنى للامتياز

## **مستوفاة**

- `check_matrix()` يبني اتحاد `objects.*.allowed_functions` ويقارنه بـ`registered_capabilities` في الاتجاهين، ويرفض الانحراف بالرمز `CTR-E006`.
- السجل يحصي **15 قدرة مسجلة**، والسياسة تحوي **4 محظورات**، والقدرة غير المسجلة في التعريف تُرفض بـE006 بدل الانهيار.
- `material_requirements` يربط 12 قدرة بمادتها، و`check_materials()` يرفض القدرة المصرح بها بلا مادة بـ`CTR-E012`.
- قتلة المصفوفة run `36472142580` حمراء في وظيفة `contracts` بسبب:
  `CTR-E006: قدرة مسجلة عامة بلا موضع ... station.sequence`.
- قتلة الامتياز run `36472144271` حمراء في الوظيفة نفسها بسبب:
  `CTR-E012: fintech: accounting.hook.declare ... accounting_hooks = 0 < 1`.
- الاتجاه الآخر لـE006 حاضر إنفاذًا في الكود، وشهادة `unknown capability copy ⇒ CTR-E006` تمر في selftest كل تشغيلة.

النتيجة: لم تعد `allowed_functions` نثرًا غير مقروء، وصار انحراف المصفوفة والامتياز بلا مادة فشلين بنيويين مسميين.

# ٢) ب٥ — المعرفات وكتالوج الأخطاء

## **مستوفاة**

- `validate.py` يحمّل `identifiers.json` و`errors.json` عبر `load_json()` fail-closed، ويفرض تطابق إصدارهما مع manifest.
- `check_identifiers()` ينفذ `CTR-E001` للنوع غير المعروف و`CTR-E010` للاشتقاق: النواة من اسم الملف، الرحلة من رأس النواة، المحطة من الرحلة الأب، والترقيم الثنائي المتتالي `01..N`، ثم المؤشر والدور والكائن من رأس النواة.
- قتلة النوع run `36472146105` حمراء وتطبع E001 صراحةً؛ ظهور E002 معها من المخطط تعزيز مستقل لا يحجب سبب E001.
- قتلة الأب run `36472149340` حمراء وتطبع E010 مرتين: الأب المخالف ثم انقطاع التسلسل `[2,3,4,5,6]`.
- الكتالوج يحوي `CTR-E001…CTR-E012` بلا تكرار. مساواة `catalog_codes == EMITTED_CODES` مفروضة بالاتجاهين؛ الزيادة أو النقص خروج fail-closed.
- كل تشغيلة تطبع `error_catalog=12 أكوادًا متسقة`، وselftest يبني شهادات E001/E010 ويقتلها.

النتيجة: فجوة م٢-075 — ملفات تعريفية غير مقروءة وأكواد بلا إنفاذ — أُغلقت.

# ٣) ب٦ — صدق manifest ومراجعه

## **مستوفاة**

- أزيلت المسارات الوهمية الأربعة. `journey/station/role/kpi` موثقة الآن كمخططات متداخلة داخل `nucleus.schema.json` بواسطة `nested_schemas`.
- `check_manifest()` يرفض: المعرف أو المسار المكرر، المسار المطلق أو الخارج بـ`..`، المسار الغائب، ملف JSON غير ممثل، والمؤشر المتداخل غير القابل للحل؛ وكلها بـ`CTR-E011`.
- عدد العقود الممثلة **9**، والمؤشرات المتداخلة **4**، وكل المراجع الحالية موجودة وتحل إلى عقدة فعلية.
- قتلة manifest run `36472151501` حمراء وتثبت الاتجاهين في السجل نفسه: مرجع `states-vanished.json` يتيم، وملف `states.json` صار بلا تمثيل.
- `guards/jsv.py` بقي مصدر المدقق الواحد، ولم يُعد فتح ما قُبل سابقًا من ب٦.

النتيجة: manifest صار قابلًا للتحقق من الشجرة الفعلية، لا قائمة ادعاءات قد تمر بمراجع غائبة.

# ٤) المقام والشاهد الموجب

run main `36472339746` على SHA المثبت خضراء، ووظيفة `contracts` خضراء. سجلها يطبع:

- `error_catalog=12 أكوادًا متسقة`.
- `matrix_union==registered(15)`.
- `material_requirements=12`.
- `manifest_contracts=9+nested×4`.

وشغلتُ مستقلًا:

`python3 contracts/validate.py --root . --selftest`

فخرج 0، ومرت الشهادات السبع، وطُبع صفر فرق المحرك وشاهد العينتين والحكم الأخضر.

**ملاحظة شكلية غير حاجبة:** `error_catalog=12` مطبوعة في سطر هوية الأداة السابق مباشرة لسطر denominator، لا في نهاية سطر denominator نفسه. المقام المطلوب حاضر كاملًا في التشغيلة ذاتها، والمساواة الثنائية مفروضة قبل الطباعة؛ لذلك لا تنشأ فجوة إنفاذ أو دليل من هذا الفصل الطباعي.
